# 论文手工作流程

## 一、锁定官方规则

生成前确认目标竞赛、届次、语言、提交格式和官方规则来源。优先使用用户提供或从官方网站取得的当届官方 LaTeX 模板、摘要页、编号页和格式说明；没有官方模板时才使用内置基线。论文固定交付 LaTeX 源码项目、实际编译 PDF 与构建清单，不生成 Word/DOCX。

## 二、检查输入

必须具备题目及附件、`题目分析报告.md`、`术语表格.md`、可运行代码、实际结果表格、原始数据图/过程图/最终结果图和已核验文献元数据。关键输入缺失时回退对应角色补齐，不能推测数值、伪造图表或编造引用。

## 三、内部论证映射

写作前建立主张—证据映射：每个结论对应公式、结果表、图、代码输出或文献。映射只用于检查，不作为额外交付物。

同时记录两类约束：当届官方页数、摘要和文件限制必须满足；论文完整度质量目标可以由用户覆盖。CUMCM 未给出更具体规则时，可按约 15000 字词单位、约 20 页规划，但不得称为官方最低要求。

## 四、W1 证据大纲

在长篇正文和 LaTeX 排版前，为每个子问题列出拟写核心主张及其公式、结果表行列、图文件、代码输出或已核验 DOI，由独立质检 Subagent 检查：

- 每个必须回答的结论类型都有精确证据路径；
- 摘要拟用关键数值与实际结果一致；
- 公式、图表和引用都有 LaTeX 章节落点。

存在核心证据缺口时返回建模手或编程手补齐；`W1` 未返回 `PASS` 不开始正文。

## 五、构建 LaTeX 论文

1. 运行 `latex_paper.py doctor` 检查官方模板需要的引擎、参考文献后端与 PDF 审计工具。
2. 用 `latex_paper.py init` 把官方模板完整复制到 `PROJECT_ROOT/完整论文-LaTeX/`；保留 `.cls`、`.sty`、`.bst`、字体和模板图片，并记录模板 URL、届次、哈希与主入口。没有官方模板时才使用内置构建基线。
3. 在复制件中填充正文、公式和已核验 BibTeX 条目，不修改原始模板或 `SKILL_ROOT`。将 `PROJECT_ROOT` 权威代码和图表复制到 LaTeX 项目后，立即用 `latex_paper.py bind` 建立资源哈希绑定；每个子问题至少安排一幅 `fig:qN-` 正式结果图。
4. 按官方模板选择 XeLaTeX、LuaLaTeX 或 pdfLaTeX，优先用 `latexmk` 编译；不启用 shell escape，不自动安装宏包，不在失败后擅自换引擎。
5. 消除编译错误、未解析交叉引用和未解析文献；每个图表都有题注、真实内容与 `label`，并由图表环境外的正文 `ref`。核对资源—源码—PDF 哈希、PDF 总页数、正文页数、附录边界、空白页、页面尺寸、字体嵌入和图片 DPI。

## 六、验证

```powershell
python ../../../../tools/latex/scripts/latex_paper.py doctor --engine xelatex --bibliography-backend <none|bibtex|biber>
python ../../../../tools/latex/scripts/latex_paper.py build "<PROJECT_ROOT>/完整论文-LaTeX/main.tex" --engine xelatex --publish "<PROJECT_ROOT>/完整论文.pdf"
python ../../../../tools/latex/scripts/latex_paper.py validate "<PROJECT_ROOT>/完整论文-LaTeX/main.tex" --pdf "<PROJECT_ROOT>/完整论文.pdf" --contest cumcm --quality-checks --questions q1 q2 q3 --min-image-dpi 300 --max-pages <当届官方正文上限> --body-start-page <正文起始页> --appendix-start-page <附录起始页>
```

没有附录时省略 `--appendix-start-page`。构建警告默认阻断发布；只有逐项核对后才能用精确允许正则和具体覆盖理由继续。自动校验通过后，仍须打开实际 PDF 抽检摘要页、正文和附录边界、分页、公式、图表、页眉页脚、字体和参考文献。

## 七、W2 论文终检

LaTeX 交付物冻结且上述门禁全部返回 0 后，按 `../../../../references/Subagent调度.md` 派发独立质检 Subagent。质检者核对当届规则、主张—证据、数值与单位、图表编号与正文引用、文献、PDF 渲染和构建清单；失败回执必须定位到页码、章节、命令或来源，并按根因返回对应角色；`W2` 未返回 `PASS` 不得交付。

## 八、交付

交付 `PROJECT_ROOT/完整论文-LaTeX/`、由其实际编译得到的 `PROJECT_ROOT/完整论文.pdf` 和 `PROJECT_ROOT/完整论文.build.json`。临时 Markdown、内部映射、检查日志和中间文件不作为交付物。
