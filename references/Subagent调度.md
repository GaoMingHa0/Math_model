# Subagent 调度与阶段门禁

Subagent 是阶段内临时协作者，不是第四个固定角色。主 Agent 负责统筹、写入权威产物和处理返工；质检 Subagent 必须未参与被审产物的编写，并默认只读。

## 默认策略

1. 默认仅派发下表中的固定质检 Subagent；调研、原型和并行实验等可选协作默认关闭。
2. 只有用户明确启用具体任务或类别时才派发可选 Subagent。用户未选择时不要反复询问，也不要暂停主流程等待授权。
3. 用户可随时增加、缩小或关闭可选协作范围；未明确启用的类别始终保持关闭。
4. 可选 Subagent 只返回范围、输入、证据或实验产物、结论、未知项和建议，不直接修改权威交付物；主 Agent 负责取舍和整合。

示例：`额外启用官方规则、附件盘点和文献调研 Subagent`、`只启用算法原型 Subagent`、`除固定质检外不使用其他 Subagent`。

## 强制原则

1. 禁止等全流程结束后才首次派发质检 Subagent；在下表规定的节点立即验收，未通过不得进入后续高成本工作。
2. 作者自检、脚本校验和独立验收三者不能互相替代。已有脚本负责机械检查，Subagent 负责独立复现、语义和证据审查。
3. 质检 Subagent 不直接修改固定交付物，只返回带证据的问题；原阶段执行者修正后，由未参与修正的质检 Subagent 复验。
4. 被验收的输入、模型、代码、结果或论文发生实质变化时，相关 `PASS` 立即失效。
5. 单阶段任务只运行该阶段的门禁，不强制拉起完整三阶段。
6. 运行环境没有 Subagent 能力时，继续运行确定性脚本并明确报告“独立验收未完成”，最终状态只能是 `BLOCKED` 或受限交付；不得声称全部门禁通过或完整完成。

## 固定门禁

| 门禁 | 派发时机 | 质检重点 | 通过后才能 |
|---|---|---|---|
| `M1` 建模终检 | 两个建模产物完成作者自检后 | 子问题覆盖、假设依据、公式与符号、单位与约束、模型数量、可实现性、验证方案、文献可追溯性 | 进入编程或交付建模产物 |
| `P1` 最小可运行结果 | 数据读取、预处理和核心求解链首次跑通后 | 从 `PROJECT_ROOT` 执行最小命令；核对真实输入或等价小实例、退出码、关键结果、单位、范围、约束和模型合同 | 开始全量计算、正式出图和参数扫描 |
| `P2` 编程终检 | 代码、结果表、三类每类至少 3 张且覆盖全部子问题的候选图和复现清单冻结后 | 独立复现、输入哈希、随机种子、关键数值、边界与量纲、收敛/鲁棒性、约束余量、运行记录、各子问题的权威结果路径与语义、复现清单和文件完整性 | 进入论文阶段或交付编程产物 |
| `W1` 证据大纲 | 主张—证据映射和论文大纲完成后 | 每个子问题的结论都有公式、结果表位置、图文件、代码输出或已核验文献，且均可落入同一 LaTeX 主稿 | 开始长篇正文和 LaTeX 排版 |
| `W2` 论文终检 | LaTeX 确定性门禁完成后 | 当届规则、主张—证据、数值与单位、图表引用、文献、实际 PDF 渲染和构建清单 | 交付 `完整论文-LaTeX/`、`完整论文.pdf` 与 `.build.json` 并宣称完整完成 |

`P1` 是纵向切片，不要求三类图、完整敏感性分析或最终性能。`W1` 是内部检查，不新增固定交付物。每个阶段可由同一名始终未参与编写和修正的质检 Subagent 连续执行中途门禁与终检；不要为每个函数、每张图或每个段落重复派发。

## M1 的语义审查与结论边界

遇到关键约束的语义、量词或索引转换，M1先读原题与必要附件，在读取作者解释和旧结论前独立记下对象、量词、检查域、邻接关系及边界；随后对照作者模型，记录一致处的依据和差异。该短记录放在现有回执证据中，不另设代理或门禁。若上下文已含作者解释，如实说明，并用从原始要求重建的候选/范围/推导补足独立性，不冒称盲审。其余环节按 [模型合同的关键逻辑检查](roles/建模手/references/前置合同.md#关键逻辑检查) 审查适用环节。优先检验会改变最终结论的定义转换、比较归因和决策步骤：可用简短推导、边界情形、反例或输入到行动的实例取得证据。不要把公式齐全、库函数可用或作者勾选完成当作语义正确；也不要求每个公式做反例测试或每个任务采用全部检查。

每项阻塞发现应给出文件位置、可核查证据、对当前主张或输出的影响，以及必须修正的内容；无证据的模型偏好、未证明必要的复杂化建议不能作为阻塞理由。参考文献中的公式和结论同样需要核对，不能因其已发表就作为正确性保证。

区分已发现的静态缺陷与待检验的数值表现：前者按严重性返修，后者在仅分析任务中可带明确的验证方法、失败条件和处置通过。未验证的拟合效果、最优参数或泛化性能必须列入未覆盖内容；已知逻辑错误不得以将来会做实验为由放行。

`PASS` 只对回执绑定的产物版本和检查范围有效，不保证模型没有遗漏，也不表示数值目标已实现。对照审查、修订说明等辅助报告的通过不更新原模型的验收状态；原模型须实际修改并复验。内部代理名称可以复用，但回执必须写清本次审查对象，不把不同对象的通过结论混用。

## 决策空间的阶段审查（按需）

离散优化、多阶段决策、策略枚举或动作删减时，读取 [决策空间与策略验证](决策空间与策略验证.md)。M1先从原题识别关键可选动作、信息和目标口径，再对照作者合同；P1/P2对薄弱限制用有区分力的可行候选、解析检查或独立界取得证据。实现独立与关键假设独立审查分开说明，不因两份程序一致就接受共同动作限制；不为所有任务增加额外门禁或复杂模型。

## 数值极值与事件的阶段审查（按需）

涉及连续域极值、首次事件或全过程约束时，读取 [数值极值与事件验证](数值极值与事件验证.md)。M1 核对主张、域、精度与验证设计；P1 用核心实现或结构等价小实例检查求解及失败识别；P2 区分复现一致性与独立正确性证据，定向检查搜索覆盖、边界及已报告的辅助极值。无需新增门禁或额外 Agent。

质检者应对会改变结论的薄弱步骤选取有区分力的推导、反例、候选构造或独立计算；说明它与作者方法仍共享哪些假设。只重跑作者命令或只复核一个给定点，不足以独立验证全域极值或首次性。回执分别记录复现证据、独立验证证据和未覆盖主张，避免对未检查字段作整体通过承诺。已知辅助数值错误按影响返修，不以主要答案不变为由覆盖；仅诊断报告通过不恢复原结果的通过状态。

## 文献使用的阶段审查

涉及外部文献时，按 [论文搜索规则](../tools/paper_search/SKILL.md) 审查；用户限定仅用附件时，不为验收强迫外部检索。`M1` 核对实际来源状态、资料时间范围、关键原文支持及方法适配，检查是否为已选模型单向寻找依据。`W1/W2` 核对借鉴方法的归属、本题独立结果与引用对应，不以文字重合度或双源收录代替真实性审查。不要求为每个引用新增 Subagent；已有可追溯且版本未变的核验记录可复用，缺关键证据时再定向补核。

## 参数估计与复杂度选择的补充门禁

反演、参数估计、标定或模型复杂度选择任务，质检者还须读取 [可辨识性与复杂度控制](可辨识性与复杂度控制.md)，按对应阶段验收；简单任务不强制执行不适用的测试。

- `M1` 检查参数依据、静态补偿风险和预定验证方案，不要求尚未实现的数值实验；未决问题须有明确的 P1 检验与回退条件，不得据此声称唯一性。
- `P1` 检查已知真值小实例或解析特例下的目标恢复/失败识别；允许门禁所需的少量初值与扰动，不等于提前全量扫描。
- `P2` 检查验证信息隔离、复杂度升级依据、目标参数稳定性和结论条件，不以拟合优度或程序收敛代替这些证据。
- 准确报告信息不足及可支持的结论可以通过质量审查；这不代表原始数值目标已实现。未解决的错误主张、无依据的精确值或未执行的必要检验仍按 `FAIL/BLOCKED` 处理。

## 派发输入

只提供完成当前验收所需的原始证据：

- 用户要求、题目和只读附件路径。
- 当前门禁的验收条款和权威产物路径。
- 输入文件版本或 SHA-256、官方规则来源、关键命令与日志。
- 上一门禁回执；复验时再提供原问题及修正证据。

不要先告诉质检 Subagent“主 Agent 认为已经正确”，也不要给出期望的通过结论。质检范围外的历史对话不传入，避免结论污染。 初次M1涉及关键语义转换且原始要求与作者产物可分开提供时，在同一名审查者、同一门禁内分两次输入：先仅给原题、必要附件和适用规则，审查者在现有回执中留下关键对象/量词/域/邻接/边界记录；随后提供作者模型与旧回执供对照。主Agent实际检查这段记录已存在再继续，不把作者产物预先混入初次派发。这个顺序无需新增代理或固定交付物。若原始文件本身混有作者解释、当前既有上下文无法分离或为复验，明确记录局限并补独立推导，不虚构未接触作者信息；主动同时读入可分开的材料后补写解释，不计为已完成先读检查，应在合适的独立上下文补核关键语义。

## 固定回执

质检 Subagent 只返回：

1. `范围`：本次审查对象、适用门禁或专项范围、已覆盖与未覆盖内容；明确区分方案审查与数值结果验证。
2. `输入快照`：被审产物及必要输入的路径、版本或 SHA-256；不得沿用其他产物的通过状态。
3. `状态`：`PASS`、`FAIL` 或 `BLOCKED`；在适用的证据或未覆盖项中分别判断用户目标满足、模型题意适配、实现验证和最优性/精度范围。分析阶段未运行的数值表现可列待验证，不虚构通过；合同内正确不等于原任务完成，用户明确限定的范围按该范围验收。
4. `证据`：适用的来源 URL、命令、退出码、文件位置、页码、推导、实例或关键数值；区分机械检查与语义检查，不把文件/格式检查数量表述为统计验证次数。
5. `发现`：按 `P0`（正确性/官方硬约束）、`P1`（复现/一致性/关键质量）、`P2`（非阻塞改进）列出。
6. `返工与待验证项`：应回到的角色、必须修正项和复验入口；尚待数值检验的内容另列方法、失败条件和处置，不与已知错误混用。
7. `P2 追溯字段`：对每个 `q1...qN` 记录权威结果路径、输入 SHA-256 和运行 ID；L2/L3 还记录基线比较、约束余量以及收敛或多种子证据路径。缺失任一适用字段时不得按完整编程交付通过。

关键约束的证据须包括原始依据、实际检查范围及能支持结论的推导/正反候选/检查结果；空泛勾选、字段齐全或检查数量本身不作为通过依据。核心可行性未通过时，与其有关的方案推荐、收益排名、风险优势及派生产物不能通过，允许保留诊断数值及无关部分的有效证据。新增实质反例会使相应旧通过结论失效，即使文件哈希未变。

存在未解决的 `P0` 或 `P1` 时只能返回 `FAIL`；缺少依赖、权限、输入或可验证证据时返回 `BLOCKED`。主 Agent 不得把 `FAIL` 改写成通过。

## 用户可选协作（默认关闭）

| 任务 | 触发条件 | Subagent 输出 | 并行与边界 |
|---|---|---|---|
| 当届官方规则核验 | 竞赛、届次或模板尚未核验 | 官方 URL、适用届次、硬约束、模板路径与哈希、冲突和未知项 | 可与附件盘点并行；论文构建必须等待 |
| 数据附件盘点 | 多附件、复杂 PDF/Excel 或字段较多 | 文件哈希、工作表、行列、首末行、字段、单位、缺失和异常 | 只读；模型选择须等待关键数据事实 |
| 文献与模型族调研 | 主张、关键词或候选模型族已经明确 | 题名、作者、年份、DOI/出版页、理论公式、适用条件、所需数据和失败风险 | 按主张簇或模型族拆分；不要按搜索引擎拆分，最终模型取舍仍由主 Agent 完成 |
| 隔离算法原型 | 某个候选算法的可实现性、接口或复杂度需要验证 | 独立目录中的最小代码、运行命令、真实输出、限制和未解决问题 | 不修改权威代码；原型通过后由主 Agent 决定是否整合 |
| 独立实验批次 | 模型、指标和参数范围已经冻结，实验之间互不依赖 | 参数、种子、命令、结果文件、耗时和失败记录 | 可并行敏感性、消融或边界实验；不得边改模型边跑实验 |
| Python/MATLAB 对照实现 | 用户明确要求双语言或需要验证跨语言一致性 | 各自隔离的实现、命令、环境、关键数值和差异 | 使用同一模型合同和输入输出；主 Agent 统一权威结果 |
| 术语与英文表达核验 | 专业领域术语较多或生成 MCM/ICM 英文论文 | 术语对照、符号与单位冲突、建议修改位置和来源 | 只提供建议，不分章节并写论文 |

## 不委派或不并行

- 不让多个 Agent 同时修改 `题目分析报告.md`、`术语表格.md`、权威代码、结果或论文正文。
- 不按章节多人并写论文，不生成互不共享正文的多份论文。
- 不把模型取舍、假设与阈值裁决、跨题耦合、用户授权和最终交付范围交给任何 Subagent。
- 依赖检查、哈希、编译、DPI、SVG 文本和文档结构等已有脚本覆盖的机械任务直接运行脚本，不再增加 Subagent。
